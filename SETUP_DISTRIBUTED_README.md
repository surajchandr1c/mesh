# 🌐 QThorium Mesh - Distributed Multi-PC Setup & Run Guide

This guide explains how to run **QThorium Mesh** across a 2-PC local network (LAN):
- **PC 2 (Main Server / Compute Node)**: Runs the Redis message broker, Track 3 gRPC transport, Track 2 FastAPI Orchestrator, Track 1 Worker inference engine (**Llama 3.2 1B** via Ollama/GGUF), and Track 4 Dashboard.
- **PC 1 (Client Node / Task Submitter)**: Submits prompts and tasks to PC 2 over the local network and receives real-time streaming tokens generated by the AI model.

---

## 📐 Architecture Overview

```
+-----------------------------------+                 +-------------------------------------------------------+
|        PC 1: Client Node          |                 |             PC 2: Main Compute Node / Server          |
|                                   |                 |                                                       |
|  [ client_submit.py ]             |                 |  +-------------------------------------------------+  |
|         │                         |                 |  | Docker: Redis Broker (:6379)                    |  |
|         │ 1. POST /api/v1/tasks   |                 |  +-------------------------------------------------+  |
|         │    /submit (JSON)       |   LAN (HTTP)    |                          ▲                            |
|         ├─────────────────────────┼────────────────►│  +-----------------------┴-------------------------+  |
|         │                         |   Port 8000     |  | Track 2 Orchestrator (:8000)                    |  |
|         │ 2. GET /api/v1/tasks    |                 |  | - Enqueues task to Redis queue                  |  |
|         │    /stream/{task_id}    |   LAN (SSE)     |  | - Streams SSE tokens from Redis                 |  |
|         │◄────────────────────────┼─────────────────┤  +-----------------------▲-------------------------+  |
|         │    (Live Token Stream)  |   Port 8000     |                          │                            |
|         ▼                         |                 |  +-----------------------┴-------------------------+  |
|  [ Real-Time Token Output ]       |                 |  | Track 1 Worker Node (Inference Engine)          |  |
|                                   |                 |  | - Dequeues task from Redis                      |  |
|                                   |                 |  | - Executes Llama 3.2 1B (Ollama / GGUF)         |  |
|                                   |                 |  | - Publishes TokenChunk to Redis stream          |  |
|                                   |                 |  +-----------------------▲-------------------------+  |
|                                   |                 |                          │ Heartbeats (:50051)        |
|                                   |                 |  +-----------------------┴-------------------------+  |
|                                   |                 |  | Track 3 gRPC Mesh Server (:50051)               |  |
|                                   |                 |  +-------------------------------------------------+  |
+-----------------------------------+                 +-------------------------------------------------------+
```

## 🖥️ PART 1: PC 2 (Main Server / Compute Node) Setup

Follow these steps on the main computer that will host the models and orchestrator.

### 1. Prerequisites on PC 2
1. **Python 3.10+** (Python 3.11, 3.12, or 3.13 installed with PATH enabled).
2. **Ollama**:
   - Download and install Ollama from [https://ollama.com/download](https://ollama.com/download).
   - Verify in PowerShell:
     ```powershell
     ollama --version
     ```
3. **Docker Desktop** (or native Redis):
   - Start Docker Desktop (ensure it is running with Linux containers / WSL 2).
   - If not using Docker, install Memurai or native Redis on port `6379`.

---

### 2. Download the Llama 3.2 1B Model on PC 2
Run this command in PowerShell to pull the exact **Llama 3.2 (1B) ~1.3 GB** model:
```powershell
ollama run llama3.2:1b
```
*(Once it launches a prompt, type `/bye` to exit. The model is now cached locally in Ollama).*

To confirm the model is installed:
```powershell
ollama list
```
You should see:
```text
NAME           ID              SIZE      MODIFIED
llama3.2:1b    baf6a787fdff    1.3 GB    ...
```

---

### 3. Clone / Open the Project on PC 2
Open PowerShell in the project root directory:
```powershell
cd C:\Users\Suraj\Desktop\Practice\Hackathone\qthorium_mesh
```
*(Replace with your actual path if different).*

---

### 4. Install Dependencies on PC 2
Install the full project requirements:
```powershell
pip install -r requirements.txt
```

---

### 5. Configure Environment Variables (`.env`)
Make sure a `.env` file exists in the project root with the following configuration:
```ini
# ==========================================
# QThorium Mesh - PC 2 Environment
# ==========================================

# Redis Message Broker
REDIS_URL=redis://localhost:6379/0

# Worker Node Configuration
NODE_ID=gaming-desktop-01
NODE_API_KEY=mesh-node-secret-key-v1
GRPC_TARGET=localhost:50051

# AI Model Configuration
TARGET_MODEL=llama3.2:1b
MODEL_PATH=track1_worker_node/models/Llama-3.2-1B-Instruct-Q8_0.gguf
OLLAMA_HOST=http://localhost:11434

# Security & Authentication
JWT_SECRET_KEY=volunpc-secret-key-change-in-production-12345
REQUIRE_AUTH=false

# RAG & ChromaDB
CHROMA_DB_PATH=./chroma_db

# Host Binding (Must be 0.0.0.0 to allow LAN access from PC 1)
API_HOST=0.0.0.0
API_PORT=8000
```

---

### 6. Allow Windows Firewall Ports on PC 2 (Crucial for Multi-PC)
To allow PC 1 to talk to PC 2, open an **Administrator PowerShell** on PC 2 and run:
```powershell
New-NetFirewallRule -DisplayName "QThorium Mesh Inbound" -Direction Inbound -LocalPort 8000,50051,6379 -Protocol TCP -Action Allow
```

---

### 7. Find PC 2's Local Network IP Address
In PowerShell on PC 2, run:
```powershell
ipconfig
```
Look for your active network adapter (`Wi-Fi` or `Ethernet`) and note the **IPv4 Address** (e.g. `192.168.1.50` or `10.8.2.105`).
👉 **Keep this IP handy — you will enter it on PC 1!**

---

### 8. Start the Complete Stack on PC 2
Open **4 separate PowerShell terminals** on PC 2 (all navigated to the project root):

#### 🔹 Terminal 1: Start Redis Message Broker
```powershell
docker compose up -d redis
```
*Verify it is running:*
```powershell
docker compose ps
```

#### 🔹 Terminal 2: Start Track 3 gRPC Mesh Server
```powershell
python track3_networking/run_grpc_server.py --port 50051
```
*Expected output: `INFO:grpc_server:Mesh gRPC Server listening securely on [::]:50051`*

#### 🔹 Terminal 3: Start Track 2 Central Orchestrator & API Gateway
```powershell
uvicorn track2_orchestrator.main:app --host 0.0.0.0 --port 8000 --reload
```
*Expected output:*
- `INFO:orchestrator:Initializing Redis pool at redis://localhost:6379/0`
- `INFO: Mounted Track 4 Dashboard & Observability APIs (/api/nodes, /api/tasks, ...)`
- `INFO: Uvicorn running on http://0.0.0.0:8000`

#### 🔹 Terminal 4: Start Track 1 Worker Node (Inference Engine)
```powershell
python track1_worker_node/main.py
```
*Expected output:*
- `INFO engine: Connected to local Ollama instance at http://localhost:11434 (model: llama3.2:1b)`
- `INFO __main__: Worker node started successfully.`
- `INFO MeshBroker: Connected successfully to Redis Broker`
- `Heartbeat | CPU: ...% | RAM: ...%`

---

### 9. Verify PC 2 Health Locally
In a browser or PowerShell on PC 2:
```powershell
Invoke-RestMethod http://localhost:8000/health
```
Expected response:
```json
{
  "status": "healthy",
  "service": "qthorium-orchestrator",
  "redis": "connected",
  "version": "1.0.0"
}
```

## 💻 PART 2: PC 1 (Client Node / Task Submitter) Setup

Follow these steps on the second computer that will send tasks to PC 2.

### 1. Prerequisites on PC 1
- **Python 3.10+** installed.
- PC 1 and PC 2 must be on the **same Wi-Fi or local area network (LAN)**.

### 2. Copy the Client Script to PC 1
You only need two files on PC 1:
1. `client_submit.py`
2. `client_requirements.txt`

*(You can copy them via USB drive, network share, or clone the repo on PC 1).*

### 3. Install Client Dependency on PC 1
Open PowerShell on PC 1 in the folder containing `client_submit.py`:
```powershell
pip install httpx
```
*(or `pip install -r client_requirements.txt`)*

---

### 4. Test Network Reachability from PC 1 to PC 2
Replace `<PC2_IP>` with the IPv4 address of PC 2 (e.g., `192.168.1.50`):
```powershell
Invoke-RestMethod http://<PC2_IP>:8000/health
```
If you get `status: healthy` and `redis: connected`, the connection is successful!

---

## 📡 Option D: Submitting via Direct cURL / PowerShell (No Script)

You can also submit tasks directly using standard tools without Python:

### Step 1: Submit Task
```powershell
$body = @{
    prompt = "What is distributed AI compute?"
    max_tokens = 150
    rag_enabled = $false
    target_model = "llama3.2:1b"
} | ConvertTo-Json

$response = Invoke-RestMethod -Uri "http://<PC2_IP>:8000/api/v1/tasks/submit" -Method Post -Body $body -ContentType "application/json"
$taskId = $response.task_id
Write-Host "Task ID: $taskId"
```

### Step 2: Stream Tokens
```powershell
curl -N "http://<PC2_IP>:8000/api/v1/tasks/stream/$taskId"
```

## 🛠️ Troubleshooting & Common Fixes

| Issue | Root Cause | Solution |
| :--- | :--- | :--- |
| **`Connection refused` on PC 1** | PC 2 Firewall is blocking port 8000, or Uvicorn is bound to `127.0.0.1` instead of `0.0.0.0`. | On PC 2, run the Firewall rule command in Admin PowerShell (`New-NetFirewallRule ... 8000`). Make sure Uvicorn was started with `--host 0.0.0.0`. |
| **`Redis service unavailable` (503)** | Redis container is stopped on PC 2. | On PC 2, run `docker compose up -d redis` and verify with `docker compose ps`. |
| **`404 Not Found` for `/api/nodes` or `/api/metrics/summary`** | Track 4 observability router was unmounted. | Patched automatically in `track2_orchestrator/main.py`. Restart Uvicorn on PC 2. |
| **`ImportError: attempted relative import with no known parent package`** | Script was executed directly without module context. | Patched in `track3_networking/run_grpc_server.py`. Run scripts from the project root. |
| **`Model 'llama3.2:1b' not found`** | Model is not downloaded in Ollama on PC 2. | Run `ollama run llama3.2:1b` on PC 2, verify with `ollama list`. |
| **`docker : The term 'docker' is not recognized`** | Docker CLI path not yet refreshed in current shell session. | Add `C:\Users\<User>\AppData\Local\Programs\DockerDesktop\resources\bin` to PATH or restart VS Code / PowerShell. |

## 📊 Summary of Ports Used

| Port | Protocol | Service | Host |
| :--- | :--- | :--- | :--- |
| **8000** | HTTP / SSE | Track 2 Orchestrator & API Gateway | `0.0.0.0` (Inbound LAN open) |
| **50051** | gRPC | Track 3 P2P Transport & Heartbeats | `0.0.0.0` (Inbound LAN open) |
| **6379** | Redis | Message Broker & Task Queue | `127.0.0.1` / Docker (PC 2 internal) |
| **11434** | HTTP | Ollama Inference Server | `127.0.0.1` (PC 2 local) |
| **3000** | HTTP | Track 4 Vite Dashboard (Optional) | `localhost:3000` |
